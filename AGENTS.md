# AGENTS.md — multi-agent-kit

Entry point for coding agents (Claude Code, Cursor, Codex) working **on** this repository, and for
agents in other projects that need to understand or explain multi-agent-kit to a user. Answer users
in their language; the bundled skills are in Russian.

## What this is

multi-agent-kit keeps skills, subagents, rules, slash commands and MCP servers in one place and
generates the files each AI coding tool expects:

| Tool | Generated files |
|------|-----------------|
| Claude Code | `.claude/skills/`, `.claude/agents/`, `.claude/rules/`, `.mcp.json` |
| Cursor | `.cursor/skills/`, `.cursor/agents/`, `.cursor/rules/`, `.cursor/commands/`, `.cursor/context/`, `.cursor/mcp.json` |
| Codex | `.agents/skills/`, `.codex/agents/*.toml`, `.codex/config.toml` |
| all | a managed block in `AGENTS.md` with the agent-kit workflow and, if enabled, the decisions process |

Three ideas carry the design:

1. **Layers.** A project's `multi-agent-kit.json` lists *sources* (this npm package, git repositories,
   local folders). Each source has `packs/`. The project enables packs and may add a *local layer*.
   Later layers override earlier ones by item name; the local layer wins.
2. **Public / private.** Sources marked private (personal or team kits) generate files that are
   excluded from git through `.git/info/exclude` and never listed in committed manifests.
3. **Ownership.** Every generated file carries `Generated by multi-agent-kit. Source: <layer>/<path>`.
   The engine only rewrites or deletes files with that marker (or the legacy markers of the old
   per-project `sync-agent-kit.mjs`) and refuses to touch anything else.

Two npm packages come from this repository:

- `multi-agent-kit` (repository root): the CLI, the public packs, the project template and the kit template.
- `create-multi-agent-project` (`create-multi-agent-project/`): a thin wrapper for
  `npx create-multi-agent-project my-app`.

## Repository map

| Path | What |
|------|------|
| `bin/multi-agent-kit.mjs` | CLI: argument parsing and output only |
| `src/config.mjs` | reads and validates `multi-agent-kit.json` |
| `src/sources.mjs` | resolves sources: `path` → installed `package` → `git` clone in `~/.cache/multi-agent-kit` |
| `src/collect.mjs` | lists pack items, applies `packs` / `include` / `exclude` / local layer, `pack.json` var defaults |
| `src/sync.mjs` | renders `{{mak.*}}` / `{{vars.*}}`, maps items to platform files, manifests, stale files, private exclude, `check` |
| `src/adopt.mjs` | copies a hand edit of a generated file back to its source |
| `src/lint.mjs` | pack validation: frontmatter, description ≤ 1024, links, secrets, deny list, vars without defaults |
| `src/decisions.mjs` | numbered RFC / ADR / OPS documents and `ACTIVE.md` |
| `src/create.mjs`, `src/init.mjs` | `create` (project template), `new-kit` (kit template), `init` (config for an existing project) |
| `packs/` | public packs: `core`, `decisions`, `thinking`, `product`, `growth`, `safety` |
| `template/` | project scaffold: `workspace/` + `web/` + `engine/`, orchestrator and zone subagents |
| `kit-template/` | scaffold of a private or team kit |
| `docs/` | `pack-format.md`, `private-and-team-kits.md` |
| `test/engine.test.mjs` | end-to-end tests through the CLI |

## Commands

```bash
npm test                                  # all tests (node:test, no dependencies)
npm run lint                              # lint the public packs
node bin/multi-agent-kit.mjs <command>    # run the CLI from a checkout
```

CLI: `sync [--check] [--update] [--take-over]`, `check`, `list`, `adopt <file>…`,
`lint [dir] [--deny file]`, `decisions create|index`, `init`, `create <dir>`, `new-kit <dir> [--public]`.

## Typical tasks

### Add or change a skill in a public pack

1. `packs/<pack>/skills/<name>/SKILL.md`, folder name = `name`, description ≤ 1024 characters that
   says **when** to use the skill. Details go to `references/`.
2. Links to other skills: `../<skill>/SKILL.md` (all skills end up side by side after sync).
3. No personal data, client names, hostnames, IPs or secrets; environment-specific values become
   `{{vars.name}}` with a neutral default in `pack.json`.
4. Do not copy third-party courses, talks or books; summarise in your own words and cite.
5. `npm run lint && npm test`.

### Change the engine

- Keep zero runtime dependencies and Node.js 20+ compatibility.
- Generation must stay deterministic: a second `sync` gives no diff, `check` passes.
- Never relax the ownership check or the private/public collision rule without a test that shows why.
- Add a test in `test/engine.test.mjs` for every behaviour change; tests drive the real CLI in temp dirs.

### Change the project template

`template/` is copied once by `create`; files there belong to the new project afterwards. Use
`{{project.name}}` and `{{kit.version}}` (replaced at creation), `{{mak.*}}` / `{{vars.*}}` in
`template/workspace/agent-kit/` (rendered by every `sync`), `_gitignore` for `.gitignore` and
`__project__` in file names. The `create` test must keep passing.

## Helping a user adopt multi-agent-kit

| Situation | What to do |
|-----------|------------|
| New project | `npx create-multi-agent-project my-app`, then fill `workspace/agent-kit/context/project.md` and `vars` |
| Existing project, no agent files yet | `npm i -D multi-agent-kit && npx multi-agent-kit init && npx multi-agent-kit sync` |
| Existing project with hand-copied skills | write the config, then `npx multi-agent-kit sync --take-over`: copies equal to the source are taken over, the rest are listed — for each, keep the project version with `adopt` or delete the file to take the source version |
| Project with the old `sync-agent-kit.mjs` | `npx multi-agent-kit init` reuses `workspace/agent-kit/` as the local layer and its `project.json` for decisions; old generated files are recognised by their marker |
| Team or personal skills | `npx multi-agent-kit new-kit <dir>`, push to a private repo, add it to `sources` (see `docs/private-and-team-kits.md`) |
| "I edited a generated file" | `npx multi-agent-kit adopt <file>`, then `sync` |
| "Where does this file come from?" | the `Source:` part of its marker, or `npx multi-agent-kit list` |
| CI | `npx multi-agent-kit check` |

When explaining, lead with the layers picture: public package → team kit → personal kit → project's
own folder → generated files for each tool.

## Rules

- Do not edit generated files in projects; edit the source and run `sync`.
- Do not commit secrets, `.env` files or values of credentials anywhere, including `vars`.
- Do not publish (npm, GitHub) or push without an explicit request from the user.
