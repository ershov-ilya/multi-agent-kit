# Переходы между состояниями

Спека почти всегда описывает **состояния**: «до ответа», «после ответа». Человек же живёт в
**переходах**: нажал — и что дальше? Нет ответа на этот вопрос — интерфейс дёргается, кнопки
исчезают без следа, ошибка теряется в `alert()`, а двойное нажатие шлёт два запроса.

Скилл нужен, чтобы в ADR рядом с каждым состоянием появилась таблица переходов. Код пишется по ней.

## Опоры дизайн-системы

Сначала найди в проекте дизайн-систему: токены движения, спиннер, тост, встроенную ошибку,
блок состояний списка. Сопоставь их строкам таблицы и пиши в ADR имена проектных токенов.
Если дизайн-системы нет, бери ориентиры из правой колонки и предложи завести токены.

| Что | Ориентир |
|-----|----------|
| Мгновенный отклик (нажатие, выбор) | 100–150 мс |
| Смена блока, раскрытие, сворачивание | 200–300 мс, стандартная кривая |
| Появление нового блока в ленте | до 500 мс |
| Спиннер | компонент кнопки в состоянии loading |
| Пульс «жду» | отдельная анимация ожидания |
| Тост | компонент уведомления поверх интерфейса |
| Ошибка рядом с местом действия | встроенное сообщение с действием «Повторить» |
| Загрузка, пусто, ошибка списка | блок состояний: скелет только для первой загрузки |
| Меньше движения | `prefers-reduced-motion: reduce` обнуляет длительности — смена без анимации |

Своих длительностей и кривых в обход дизайн-системы не заводить.

## Алгоритм

1. **Выпиши состояния** объекта, включая служебные: `idle`, `pending`, `success`, `error`,
   `editing`, `disabled` (срок вышел, нет прав), `stale` (пришло обновление с сервера).
2. **Нарисуй переходы**: каждое событие (нажатие, ответ сервера, ошибка, таймаут, событие из
   другой вкладки или от другого человека) → из какого состояния в какое.
3. **Выбери стратегию отклика** для каждого перехода по таблице ниже.
4. **Опиши, что видно** в каждый момент: что меняется сразу, что с анимацией, что после ответа.
5. **Опиши отказ**: откат, сообщение, повтор, что сохраняется из ввода человека.
6. **Проверь края**: двойное нажатие, медленная сеть (3 с+), офлайн, ответ после ухода с экрана,
   тот же объект на другом экране, 409/срок вышел, экранный диктор, уменьшенное движение.
7. **Запиши в ADR** разделом «Переходы» (шаблон ниже).

## Стратегия отклика

| Ситуация | Стратегия |
|----------|-----------|
| Действие почти всегда успешно, обратимо, результат известен заранее (отметка, переключатель, лайк) | **Optimistic update**: показать итог сразу, запрос в фоне, при ошибке — откат с объяснением |
| Результат зависит от сервера (создание, поиск, ссылка, код) | **Pending на месте действия**: кнопка в состоянии loading, текст кнопки не меняется, повторное нажатие невозможно |
| Дольше 1 с с известным ходом (файл, несколько шагов) | **Прогресс**: полоса или «Шаг 2 из 3», а не бесконечный спиннер |
| Дольше 10 с или в фоне (разбор документа, рассылка) | Сразу сказать, что идёт, дать уйти; результат — событием в интерфейсе или тостом |
| Необратимое (удаление, отправка другому человеку) | Без optimistic: подтверждение, `pending`, итог только после ответа |

Спиннер появляется **не сразу**, а через 300 мс ожидания: быстрый ответ не должен мигать.
Показанный спиннер держится минимум 400 мс — без дрожи.

## Анимация смены состояния

- Меняется **то, на что нажали**, остальное — следом. Нажатая кнопка получает выбранный вид за
  время мгновенного отклика; соседние гаснут; блок схлопывается и раскрывается в новое содержимое
  за время смены блока.
- Высота блока меняется плавно (`grid-template-rows: 1fr → 0fr` или измеренная высота), лента
  не прыгает. Новый текст — `opacity 0 → 1` и сдвиг на 4 px.
- Новый блок от сервера появляется с анимацией появления и только если человек у низа ленты;
  иначе — счётчик «ниже новое», без прокрутки за человека.
- Анимация не задерживает ввод: следующее нажатие доступно сразу после смены состояния.
- `prefers-reduced-motion` — мгновенная смена, смысл тот же.

## Обратная связь

- **Итог виден на месте действия** всегда. Тост дублирует, а не заменяет.
- **Тост** — когда эффект не виден на экране: ушло другому человеку, сохранилось в другом разделе,
  фоновая операция закончилась. 3 с, одна строка, без кнопок, кроме «Отменить», где отмена возможна.
- **Ошибка** — встроенное сообщение внутри того же блока: что не получилось, что сохранено,
  «Повторить». Никаких `alert()`. Ввод человека не теряется.
- **Офлайн**: optimistic-изменение остаётся с пометкой «Сохраню, когда появится связь» и
  повторяется при `online`; необратимые действия заблокированы с объяснением.
- **409 / срок вышел / нет прав**: не ошибка сети — блок переходит в `disabled` с причиной, без
  «Повторить».

## Целостность

- Один источник правды на клиенте для объекта, видного в нескольких местах (список и карточка):
  изменение в одном месте сразу видно в другом.
- Повтор того же действия, пока идёт запрос, игнорируется; повтор уже применённого значения
  запроса не шлёт.
- Ответ сервера, пришедший после ухода с экрана, применяется к данным, но не открывает тостов
  о старом действии на чужом экране.
- Сервер — арбитр: после успеха состояние берётся из ответа, а не из оптимистичной догадки.

## Доступность

- Блок в `pending` — `aria-busy="true"`; итог объявляется `aria-live="polite"` одной фразой.
- Фокус после смены: на следующий осмысленный элемент («Изменить»), не теряется в `body`.
- Цвет не единственный признак выбранного: текст или иконка рядом.

## Шаблон раздела ADR

```markdown
### Переходы

| Из | Событие | В | Что видно сразу | После ответа сервера | При ошибке |
|----|---------|---|-----------------|----------------------|-----------|

Стратегия: optimistic / pending / прогресс / фон — почему.
Тайминги: токены дизайн-системы. Уменьшенное движение: …
Тост: когда и текст. Ошибка: встроенное сообщение, текст, «Повторить».
Края: двойное нажатие, медленная сеть, офлайн, другой экран, срок вышел.
Доступность: aria-busy, aria-live, фокус.
```

## Анти-паттерны

- Кнопки исчезают, текст появляется — без промежутка и без смены высоты по анимации.
- `alert()` на ошибку и тихий откат без объяснения.
- Спиннер на каждое нажатие, даже на 80 мс.
- Тост как единственный признак, что что-то сохранилось.
- Optimistic для необратимого.
- Анимация, которую нельзя пропустить, и анимация дольше 500 мс.
