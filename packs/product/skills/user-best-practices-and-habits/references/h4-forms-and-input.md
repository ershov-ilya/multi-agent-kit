# H4. Формы и ввод

> Форма — место, где уходят. Каждое поле, каждая ошибка без объяснения, каждое «обязательно» без причины снижают завершение. Люди ждут, что устройство заполнит за них, а сервис примет ввод в любом разумном виде.

Источники: Baymard checkout и form usability (2024–2026), Zuko form benchmarks 2025–2026 (≈66–68 % завершают начатую форму; десктоп ≈54 % vs мобильный ≈48 % от просмотра), NN/g form design, Luke Wroblewski «Web Form Design», WebOTP/Autofill specs, FIDO 2026 (47 % бросают вход, если не помнят пароль; 75 % включили passkey хотя бы раз), Apple HIG/Material text fields.

## Привычки

| Привычка | Что наблюдаем | Что это значит | Типичная ошибка |
|---|---|---|---|
| **Ждут автозаполнения** | Телефон, email, имя, адрес, карта — из системы или менеджера; код из SMS — автоподстановка | Правильные `autocomplete`/`textContentType`, WebOTP, один-два поля на экран | Поля без атрибутов; код вводят вручную |
| **Бросают на лишнем** | Каждое поле — минус конверсия; «необязательные» заполняют редко и раздражаются | Только нужное; необязательное — позже или с явной пользой | Анкета «на будущее» |
| **Читают подпись, не плейсхолдер** | Плейсхолдер исчезает при вводе; его принимают за заполненное | Подпись над полем всегда видна; плейсхолдер — пример формата | Подпись только плейсхолдером |
| **Ошибку хотят рядом и сразу** | Валидация при уходе с поля (не при каждом символе), текст у поля, цвет + иконка + текст | Инлайн-валидация по blur; сводка сверху только при отправке | Красная рамка без текста; ошибки только после отправки; валидация на каждый символ |
| **Клавиатура должна соответствовать** | Цифровая для телефона и кода, email-клавиатура для почты, «Готово/Далее» по смыслу | `inputmode`, `type`, `enterkeyhint` | Буквенная клавиатура для кода |
| **Вставка из менеджера паролей** | Вставку блокируют → уход | Разрешать вставку всегда; показать пароль по кнопке | `onpaste="return false"` |
| **Телефон в любом формате** | +7, 8, с пробелами, скобками | Принимать всё, нормализовать (Postel); маска подсказывает, не мешает | Жёсткая маска, ломающая вставку |
| **Email с опечатками** | gmail.con, mail.ry | Подсказка «вы имели в виду…»; не блокировать | Отклонить без подсказки |
| **Имя — не «First/Last»** | В России — имя и фамилия, отчество по желанию; имя может быть одним словом; латиница/кириллица | Одно поле «Как вас называть» для большинства продуктов; ФИО только где требует закон | Три обязательных поля ФИО |
| **Дата — не календарь-пикер для дня рождения** | Для далёких дат удобнее ввод или три селекта; календарь — для ближайших дат | Пикер под задачу; для возраста — спросить возраст или год | Календарь с перелистыванием 30 лет |
| **Адрес ждут с подсказкой** | Автодополнение по вводу (ДаДата-подобное); не 6 полей | Автодополнение + редактирование | Индекс, область, район вручную |
| **Селект на 5+ вариантах, радио на 2–4** | Выпадающий список скрывает варианты | Радио/чипсы для ≤ 5; поиск в селекте для длинных | Селект для «да/нет» |
| **Галочки не предзаполняют** | Предотмеченные согласия воспринимаются как обман и незаконны для ПДн/рекламы | Пустые галочки с понятным текстом | Предзаполненное «согласен на рассылку» |
| **Длинная форма — по шагам** | Многошаговая с прогрессом завершается лучше одной длинной, если шаги осмысленны | 3–5 вопросов на шаг, прогресс, возврат, сохранение черновика | 15 полей на одном экране или 15 шагов по одному полю |
| **Загрузка фото** | Ожидают камеру/галерею, кроп, сжатие на устройстве, предпросмотр | Нативный пикер, кроп, индикатор, повтор при ошибке | Требование файла < 2 МБ без сжатия |
| **Капча — уход** | Любая капча снижает завершение; невидимые лучше | Капча только после сигнала злоупотребления | Капча на каждой форме |
| **Свободный текст пугает** | Большое пустое поле без примера → короткий бессмысленный текст или уход | Пример, подсказки, чипсы, лимит с счётчиком, ИИ-помощь (см. `h9`, `h13`) | «Расскажите о себе» |

## Лучшие практики

- **Одна колонка**, поля во всю ширину, подпись над полем, пример в плейсхолдере.
- **Минимум полей**: правило «что сломается без этого поля»; остальное — прогрессивно.
- **Автозаполнение**: `autocomplete="tel|email|name|one-time-code|street-address"`, `textContentType` на iOS, WebOTP на Android/Chrome; поля в том порядке, в котором их отдаёт автозаполнение.
- **Валидация**: по уходу с поля для формата; при вводе — только для «пароль достаточно длинный»-индикаторов; текст ошибки говорит, что исправить; поле с ошибкой в фокус при отправке.
- **Тексты ошибок**: «Введите телефон в формате +7 …» вместо «Неверный формат»; без обвинения, без кода.
- **Необязательное помечать как «необязательно»**, а не обязательное звёздочкой, если обязательных большинство.
- **Кнопка отправки — глагол результата** («Получить подборку», «Отправить запрос»), активна всегда, при ошибке показывает, что не так, а не серая без объяснения.
- **Сохранение черновика** при переключении приложения и при ошибке сети; восстановление при возврате.
- **Код из SMS/письма**: 6 цифр, отдельные ячейки или одно поле с автоподстановкой, кнопка «отправить снова» с таймером, вставка работает.
- **Пароль**, если есть: показать/скрыть, вставка, без правил «спецсимвол»; лучше passkey или код.
- **Шаги**: прогресс («Шаг 2 из 3 — Контакты»), «назад» сохраняет, «пропустить» для необязательных.
- **Фото**: кроп на устройстве, сжатие, предпросмотр, «заменить», понятный лимит.
- **Доступность**: подписи связаны с полями, ошибки объявляются, порядок табуляции, достаточный размер.

## Вопросы для брейншторма

1. Для каждого поля: что сломается, если его не спросить сейчас?
2. Что заполнит устройство само и настроены ли атрибуты автозаполнения?
3. Какая клавиатура откроется на каждом поле?
4. Что увидит человек при ошибке: где, какой текст, что делать?
5. Примет ли форма телефон с 8 и пробелами, email с опечаткой, имя одним словом?
6. Есть ли предзаполненные галочки?
7. Что произойдёт с введённым при переключении приложения, ошибке сети, нажатии «назад»?
8. Нужна ли капча и когда она появляется?
9. Для свободного текста: какой пример, подсказки, лимит?
10. Какой глагол на кнопке и что происходит, если она «не работает»?

## Признаки проблемы

Подпись только плейсхолдером · красная рамка без текста · буквенная клавиатура на коде · заблокированная вставка · ФИО из трёх обязательных полей · календарь для даты рождения · предзаполненная галочка рассылки · капча на входе · серая кнопка без объяснения · «Неверный формат».
