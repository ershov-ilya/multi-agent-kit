# Чеклисты

Семь списков по ситуациям. Каждый пункт помечен доменом, чтобы при «нет» открыть нужный файл. Чеклист — страховка от забытого; путь и привычки — в `playbook.md`.

## 1. RFC / брейншторм фичи

**Рамка**
- [ ] Пользователь, устройство, момент, частота описаны; JTBD одной строкой (`playbook`).
- [ ] Путь по шагам: что видит первым, что ждёт, сколько ждёт, что может пойти не так.
- [ ] Ведущие домены названы; по ним пройдены «Вопросы для брейншторма».

**Интерфейс**
- [ ] Заголовок каждого экрана отвечает на вопрос пользователя; один фокус (H1).
- [ ] Ценность до регистрации или регистрация ≤ 30 с; пустые состояния спроектированы; экран «что дальше» после первого действия (H2).
- [ ] Навигация стандартная; «назад» предсказуем; у объектов есть ссылки (H3).
- [ ] Формы: минимум полей, автозаполнение, инлайн-ошибки с текстом, черновики (H4).
- [ ] Отклик: < 400 мс видимый, скелетоны, оптимистичные действия, undo вместо подтверждений, тексты ошибок, офлайн (H5).

**Поведение**
- [ ] Уведомления: классы, дефолты, предзапрос в момент ценности, выбор канала, частота, тихие часы (H6).
- [ ] Видимость у личных полей; причина у каждого запроса данных; жалоба/блок/удаление/отзыв на месте (H7).
- [ ] Социальное: структурированный контакт, статусы запроса со сроками, мягкий отказ, без read receipts, переход в мессенджер (H8).
- [ ] Контент: примеры до поля, структура вместо свободного текста, черновик, лимит, OG-превью, актуальность (H9).
- [ ] Выбор: 3–5 вариантов, честный дефолт, причина рекомендации, обратимость, без ложного дефицита (H10).
- [ ] Удержание: тип продукта назван; критическое событие и частота; крючок на завтра; событийные триггеры; честный конец (H11).

**Среда**
- [ ] Поиск: толерантность, подсказки, ноль результатов с выходом, вопросы целиком (H12).
- [ ] ИИ: чипсы, умная форма, стриминг, опора, «почему», подтверждение действий, человек рядом, пометка ИИ (H13).
- [ ] Доступность: 200 % шрифт, темы, контраст, семантика, клавиатура, бюджет производительности, локаль (H14).
- [ ] Платформа: web/Mini App/нативное обосновано; конвенции платформы; системная «назад»; RuStore/СБП при необходимости (H15).
- [ ] Деньги: пейвол после ценности, три тарифа, цена в месяц, явное автопродление, отмена в 1–2 шага, СБП (H16).
- [ ] Рынок: чеклист `ru-market.md` пройден для российской аудитории.

**Итог**
- [ ] Бенчмарки для ключевых шагов записаны с источниками; цели обоснованы (`benchmarks`).
- [ ] Этика: тёмные паттерны перечислены и отвергнуты (`principles`).
- [ ] Раздел «Пользователь» в RFC написан по шаблону; метрики и антиметрики названы.

## 2. Спека экрана

- [ ] Первое, что видит человек, — заголовок-ответ и одно главное действие (H1).
- [ ] Текст экрана написан до макета; заголовок + ≤ 2 строки; глагол на кнопке (`principles`).
- [ ] Главное действие в зоне большого пальца, ≥ 44 pt (H1, `principles`).
- [ ] Состояния: пустое, загрузка (скелетон), ошибка, офлайн, частичные данные, много данных (H5).
- [ ] «Назад» и закрытие определены; состояние в URL (H3, H15).
- [ ] Поля: подпись над полем, пример, автозаполнение, клавиатура, валидация, тексты ошибок (H4).
- [ ] Личные данные: видимость и причина рядом (H7).
- [ ] Иконки с подписями; статусы цвет + иконка + текст (H1, H14).
- [ ] Макет при 200 % шрифта, в тёмной теме, на 360 px ширины (H14).
- [ ] Микротексты: тон, «вы», без жаргона, без англицизмов (H14, `ru-market`).
- [ ] Что измеряем на этом экране (`benchmarks`).

## 3. Проверка ADR / OPS

- [ ] Решение влияет на латентность? Пороги 400 мс / 1 с / 10 с соблюдены на среднем Android по 4G (H5, H14).
- [ ] Деградация при отказе зависимости спроектирована как состояние экрана, а не как «500» (H5).
- [ ] Офлайн и повторы: очередь, черновики, идемпотентность (H5).
- [ ] Выкладка: окно вне пиков активности пользователей (утро, вечер); уведомление о недоступности, если > минуты (`ru-market`).
- [ ] Совместимость с отстающими клиентами; принудительное обновление только критичное (H15).
- [ ] Изменения в уведомлениях: классы, частота, тихие часы, миграция настроек (H6).
- [ ] Изменения в данных: что увидит пользователь (удаление, экспорт, видимость) (H7).
- [ ] Изменения в поиске/ранжировании: «почему» и «не то» сохранены; холодный старт (H12, H13).
- [ ] Платформенные ограничения РФ учтены: CDN, шрифты, мессенджеры, сторы (`ru-market`, H15).
- [ ] Метрики и антиметрики после выкладки: что смотрим в первые 24 часа и 7 дней.

## 4. Аудит существующего экрана (за час)

1. Пройди экран как новичок на среднем Android одной рукой: что первое, что непонятно, где замер (H1, H2).
2. Нажми «назад» на каждом шаге (H3).
3. Заполни форму с опечатками, вставкой, другой раскладкой; вызови каждую ошибку (H4).
4. Обрежь сеть посреди действия; нажми кнопку дважды (H5).
5. Посмотри уведомления за неделю активного пользователя: сколько, когда, о чём (H6).
6. Найди «пожаловаться», «удалить аккаунт», «кто это видит», «отозвать» (H7).
7. Проверь карточку человека/объекта на три вопроса: кто, что общего, безопасно ли (H8).
8. Посчитай варианты на экранах выбора; найди дефолт и его причину (H10).
9. Введи вопрос целиком и запрос с опечаткой в поиск; получи ноль результатов (H12).
10. Если есть ИИ: пустой старт, опора, «почему», ошибка, путь к человеку (H13).
11. Включи 200 % шрифт и тёмную тему; пройди с клавиатуры/VoiceOver (H14).
12. Открой ссылку из Telegram; посмотри превью и первый экран (H15, `ru-market`).
13. Пройди оплату до отмены подписки (H16).
Выход: список нарушений по приоритету (ломает первую сессию → теряет доверие → раздражает), быстрые победы, метрики.

## 5. Новое уведомление

- [ ] Класс: транзакционное / ожидаемое / маркетинг; дефолт для класса (H6).
- [ ] Триггер — реальное событие; ведёт в один тап к действию (H6, H11).
- [ ] Текст: кто + что + про что, ≤ 2 строк; deep link (H6).
- [ ] Группировка и лимит частоты; тихие часы по поясу (H6, `ru-market`).
- [ ] Отписка от этого типа и от всего; синхронизация «прочитано» (H6).
- [ ] Канал по выбору пользователя; запасной канал (H6, `ru-market`).
- [ ] Правовая классификация (реклама?) — `legal` L6.
- [ ] Антиметрика: отключения после отправки.

## 6. Новая форма

- [ ] Для каждого поля: что сломается без него сейчас (H4).
- [ ] Атрибуты автозаполнения и типы клавиатур (H4).
- [ ] Подпись над полем, пример в плейсхолдере, лимит (H4).
- [ ] Толерантность к формату: телефон, email, имя (H4, H14).
- [ ] Валидация по уходу с поля; тексты ошибок «что сделать» (H4, H5).
- [ ] Галочки пустые; согласия отдельно (H7, `legal`).
- [ ] Черновик при переключении и обрыве; кнопка-глагол с состоянием (H4, H5).
- [ ] Свободный текст: примеры до поля, структура, подсказки, ИИ-черновик (H9, H13).
- [ ] Видимость и причина у личных полей (H7).
- [ ] Многошаговость: прогресс, назад, пропуск (H4).

## 7. Фича с ИИ

- [ ] Что видит человек до ввода: чипсы, пример, границы (H13).
- [ ] Умная форма или беседа; число реплик до результата (H13).
- [ ] Стриминг/стадии; остановка (H13, H5).
- [ ] Опора у ответов; честное «не знаю» (H13, H7).
- [ ] «Почему» и «не то» у каждого результата (H13, H10).
- [ ] Побочные действия только с подтверждением и предпросмотром (H13).
- [ ] Путь к человеку и обычному интерфейсу (H13).
- [ ] Пометка ИИ; название по пользе; строка о данных (H13, H7).
- [ ] Память по согласию с удалением (H13).
- [ ] Антиметрика доверия: повторное использование после первой сессии (H13, `benchmarks`).
- [ ] Безопасность и право — `secure-by-design` D12, `legal` L9.
