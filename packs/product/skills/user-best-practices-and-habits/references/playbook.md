# Плейбук сессии по привычкам пользователей

Как вести брейншторм, ревью RFC или спеки экрана, проверку ADR/OPS и аудит по карте доменов из `SKILL.md`. Файл задаёт процесс; содержание привычек и практик — в файлах `h1`–`h16`.

## Пять режимов

| Режим | Когда | Вход | Выход |
|---|---|---|---|
| **Брейншторм фичи** | Фича на бумаге или в голове | Идея, пользователь, момент использования | Путь с привычками, практики, риски, раздел «Пользователь» для RFC |
| **Ревью RFC / спеки экрана** | Документ написан | Текст, макеты, описание флоу | Находки: элемент → привычка/закон → что увидит пользователь → исправление → серьёзность; вердикт |
| **Проверка ADR / OPS** | Архитектурное или операционное решение влияет на опыт (латентность, офлайн, уведомления, выкладка) | Текст решения | Пользовательские последствия решения и требования к нему (пороги отклика, деградация, тексты, окна выкладки) |
| **Аудит существующего экрана** | Метрика просела или «не нравится» | Экран, данные по воронке, если есть | Список нарушений привычек по приоритету, быстрые победы, что измерять |
| **Короткий вопрос** | «Сколько пунктов в таб-баре?» | Вопрос | Прямой ответ с нормой, источником, ошибкой, примером |

## Что собрать до начала

1. **Пользователь**: возраст и цифровой опыт, устройство (средний Android? iPhone?), платформа (браузер, Telegram, приложение), частота (ежедневно / раз в месяц / один раз), момент и место (в дороге, за столом, в очереди), состояние (спешит, тревожится, скучает).
2. **Работа** (JTBD): «Когда [ситуация], я хочу [мотивация], чтобы [результат]». Функциональная, эмоциональная, социальная стороны.
3. **Привычки из соседних продуктов**: откуда человек придёт и что там считается нормой (мессенджер, маркетплейс, банк, соцсеть, знакомства).
4. **Путь**: экраны и шаги от триггера до результата; что первым на каждом; сколько ждёт; что может пойти не так.
5. **Ограничения**: рынок (см. `ru-market.md`), платформа, аудитория 18+, регуляторика (см. `legal`).
6. **Данные**, если есть: воронка, время на шаге, где уходят, opt-in, D1/D7.

Чего нет — зафиксируй как допущение.

## Алгоритм по шагам

### Шаг 1. Пользователь и работа
Одна строка JTBD и портрет в три строки. Если портретов несколько (новичок / вернувшийся / опытный), путь строится для каждого — привычки различаются.

### Шаг 2. Путь по шагам
Таблица: шаг → что видит первым → что должен сделать → что ждёт → привычка, которая здесь решает → риск. На каждом шаге спроси: «что человек сделает по привычке, если ничего не прочтёт?»

### Шаг 3. Проход по доменам
Ведущие домены из таблицы «фича → домены» ниже. Открой файл, пройди «Вопросы для брейншторма». Остальные — одной строкой.

| Фича | Ведущие домены |
|---|---|
| Регистрация, вход | H2, H4, H5, H7, H15 |
| Онбординг, первый экран | H2, H1, H9, H3 |
| Профиль, анкета, описание | H9, H4, H7, H14 |
| Лента, подборка, список | H1, H10, H12, H11 |
| Карточка человека/объекта | H1, H7, H10, H8 |
| Оффер, запрос, согласие, контакт | H8, H7, H5, H6 |
| Уведомление, письмо, бот | H6, H1, H8, H15 |
| Ассистент, чат с системой | H13, H9, H7, H5 |
| Поиск, фильтры | H12, H10, H1 |
| Оплата, тариф, подписка | H16, H10, H7, H4 |
| Настройки, приватность, удаление | H7, H3, H10 |
| Пустое состояние, ошибка, офлайн | H5, H2, H1 |
| Возвращение, повтор, привычка | H11, H6, H8 |
| Новая платформа (Mini App, PWA, приложение) | H15, H3, H14 |

### Шаг 4. Законы и эвристики
Пройди по короткому списку из `principles-and-frameworks.md`: Jakob, Hick, Fitts, Miller/Cowan, Doherty, peak-end, Zeigarnik, goal-gradient; 10 эвристик Нильсена. Для каждого нарушения — строка.

### Шаг 5. Бенчмарк
Из `benchmarks.md` — норма для шага. Цель: не «лучше всех», а «понимаем, где мы и почему».

### Шаг 6. Практики
Для каждой привычки с риском — конкретное решение: элемент экрана, текст, порядок, дефолт. С примером формулировки и анти-примером. Проверь, что решение узнаваемо (Jakob) и не добавляет шага.

### Шаг 7. Этика
Тёмные паттерны по списку в `principles-and-frameworks.md`; честная альтернатива для каждого соблазна. Границы — `nudge`, `legal`.

### Шаг 8. Выдача
Сводка, путь, практики, бенчмарк и метрики, этика, раздел «Пользователь» для RFC.

## Карточка привычки

Используй, когда нужно зафиксировать привычку как аргумент в RFC или ADR.

```
Привычка: <одной строкой, как ведёт себя человек>
Домен: Hx · Сила: сильная / средняя / слабая · Аудитория: все / сегмент
Откуда известно: <исследование, год; или наблюдение продукта>
Что ожидает: <конкретное поведение интерфейса>
Что делаем: <решение в экране/тексте>
Анти-пример: <как делать нельзя>
Что измерим: <метрика и порог>
```

## Шаблон раздела «Пользователь» для RFC

10–25 строк.

```
## Пользователь

**Кто и когда.** <портрет, устройство, момент, частота>
**Работа.** Когда …, хочу …, чтобы …

**Путь.**
| Шаг | Видит первым | Делает | Ждёт | Привычка | Решение |

**Ключевые практики.**
1. <привычка> → <практика>, закон/источник
2. …

**Пороги.** Отклик: … Форма: … полей. Уведомления: просим после … Бенчмарк: …

**Пустые и ошибочные состояния.** <что показываем, что предлагаем>

**Этика.** <что соблазняло и почему отказались>

**Что измеряем.** <3–5 метрик с порогами>
```

## Пример мини-сессии: «первый экран после входа для новичка в сервисе знакомств по запросу внутри сообщества»

**Пользователь.** 25–45 лет, средний Android, пришёл по ссылке из Telegram сообщества, в дороге или вечером, ожидает «как в Telegram и как в маркетплейсе». Работа: «Когда мне нужен конкретный человек (специалист, попутчик, партнёр по хобби) в моём кругу, я хочу описать, кого ищу, чтобы получить несколько подходящих вариантов и выбрать, кому открыться».

**Путь и привычки.**
| Шаг | Видит первым | Ждёт | Привычка | Риск |
|---|---|---|---|---|
| Экран после входа | Заголовок и одно поле | Понять, что делать за 3 секунды | H1: сканирует; H2: ищет результат | Пустой экран «Добро пожаловать» без действия |
| Поле «кого ищу» | Пустое поле | Пример или подсказку | H9: боится создавать; H13: пустой промпт | Абстрактное «расскажите» |
| Ожидание подборки | Спиннер | Понять, что происходит и сколько ждать | H5: не терпит неизвестности | 5 секунд без слов |
| Подборка | 3–5 карточек | Быстро понять, кто подходит; кто это видит | H10: мало вариантов; H7: приватность | 20 карточек с фильтрами |
| Запрос контакта | Кнопка | Понять, что произойдёт и что увидит другой | H8: двойное согласие; H7: контроль | Неясно, раскроется ли телефон |
| После запроса | Пустота | Что дальше и когда | H6: причина вернуться; H5: статус | Тишина |

**Практики.**
1. H2/H1: заголовок — вопрос работы: «Кого вы ищете в сообществе?», одно поле, одна кнопка; без тура.
2. H9/H13: три чипса-примера под полем («репетитор по математике рядом», «попутчик на выходные в горы», «кофаундер с опытом в продажах»); плейсхолдер — живой пример, не инструкция.
3. H5: скелетон карточек сразу, текст «подбираем среди 37 участников…», после 3 с — «ещё секунду», после 10 с — объяснение и кнопка «написать мне, когда будет готово».
4. H10: 3–5 карточек, «показать ещё» вместо фильтров; одна причина совпадения на карточке («тоже ищет попутчика на выходные»).
5. H7/H8: под кнопкой «Предложить познакомиться» — «Человек увидит ваше описание без имени и контактов. Контакты откроются, только если согласитесь оба».
6. H6/H5: после запроса — экран «Что дальше»: «Обычно отвечают за 1–3 дня. Сообщим в Telegram/на почту» и переключатель канала; первый запрос разрешения на уведомления — здесь.

**Бенчмарк.** Конверсия первого экрана в отправленный запрос: цель ≥ 40 % новичков (аналог форм с одним полем: 60–70 % завершений от начавших, Zuko 2025, минус неопределённость задачи). D7 для социальных: медиана ~10 %, наша цель выше за счёт конкретной работы.

**Этика.** Соблазн показать «3 человека уже заинтересовались» без данных — отказ (ложный социальный сигнал). Соблазн предзаполнить галочку уведомлений — отказ.

**Измеряем.** Доля дошедших до подборки; время до первого запроса; доля запросов с подсказки; отказов от уведомлений при запросе; возвратов по уведомлению.
