# Лендинг, сайт и коммуникация через работу

> Страница работает, когда человек в первые секунды узнаёт свою ситуацию и видит прогресс, который ему обещают, его словами. Остальное — снятие тревог и уважение к привычке. Этот файл переводит работу, силы и таймлайн в структуру и текст страниц. Для каналов, бюджета и измерения конверсии смотри скилл `internet-marketing`; для поискового спроса — `seogeo`; для поведенческих механик страницы — `nudge`.

## Hero-блок как формула работы

Базовая формула первого экрана:

```
Заголовок:    <прогресс> для <исполнитель в обстоятельствах>
Подзаголовок: Когда <ситуация>, <продукт> помогает <прогресс> без <главная тревога>
Доказательство: <один факт или история переключения>
Действие:     <глагол первого Little Hire>, не «зарегистрироваться»
```

Пример (сервис отчётов для агентств):
- Заголовок: «Отчёт клиенту за 20 минут вместо половины дня».
- Подзаголовок: «Когда в конце месяца нужно свести пять рекламных кабинетов и не отправить ошибку, сервис собирает цифры сам и подсвечивает странное».
- Доказательство: «Агентство из 12 человек перестало переделывать отчёты после отправки».
- Действие: «Собрать первый отчёт».

Проверки hero:
- **Узнавание**: исполнитель в обстоятельствах прочитал первую строку и сказал «это про меня»? Тест: показать пяти людям из сегмента на 5 секунд и спросить, для кого это.
- **Прогресс его словами**: формулировка взята из интервью или отзывов, не из нашей терминологии.
- **Без категории в заголовке**, если категория наследует тревогу («ещё одна CRM»). Категория уместна в подзаголовке или навигации, если человек в активном поиске ищет именно её.
- **Один прогресс**. Три обещания в заголовке = три работы = ноль узнавания.

## Структура страницы по силам

Порядок блоков повторяет порядок, в котором человек проходит силы:

| Блок | Сила | Что содержит | Типичная ошибка |
|---|---|---|---|
| 1. Hero | Push → pull | Ситуация, прогресс, одно доказательство, действие | Фичи вместо прогресса |
| 2. Узнавание ситуации | Push | 3 обстоятельства или боли словами людей («сводите пять кабинетов руками», «находите ошибку после отправки») | Обобщения («экономьте время») |
| 3. Как выполняется работа | Pull | Шаги карты работы, которые закрываем, в порядке работы, не в порядке меню | Список фич по алфавиту |
| 4. Снятие тревог | Тревога | Импорт, пробный период, безопасность, цена, «что если не подойдёт», кто отвечает | Прятать цену, общие слова про безопасность |
| 5. Истории переключения | Push + pull + тревога | Отзывы как истории: что было, что случилось, что теперь | «Отличный продукт, рекомендую» |
| 6. Переход со старого | Привычка | Миграция, совместимость, сосуществование, «ничего не потеряете» | Молчание про старое решение |
| 7. Честные границы | Тревога «где подвох» | Для кого не подходит, чего не делаем | Отсутствие; человек ищет подвох сам |
| 8. Действие | Решение | Повтор первого Little Hire, дедлайн или причина «сейчас», если он честный | Искусственная срочность |

Не каждый лендинг использует все восемь; порядок важнее полноты. Блок тревог выше блока фич на страницах для фазы решения.

## Страницы под фазы таймлайна

Один лендинг не обслуживает все фазы. Разводи по страницам и каналам:

| Фаза | Что нужно человеку | Тип страницы | Метрика |
|---|---|---|---|
| **Первая мысль** | Назвать проблему | Статья «почему <ситуация> выматывает», пост, разговор | Дочитывание, подписка на контент |
| **Пассивный поиск** | Понять, что решения бывают | Истории «как <роль> перестал <боль>», разборы, гайды без регистрации | Возврат, подписка |
| **Активный поиск** | Критерии и сравнение | Страницы «vs», «альтернативы X», калькуляторы, демо без регистрации, честная таблица | Переход к цене, запрос демо |
| **Решение** | Снять тревоги, дедлайн | Цена с ответами на тревоги, FAQ по тревогам, гарантия, кейс похожего человека | Оплата, старт пробного |
| **Онбординг** | Первый результат | Приветствие с вопросом о работе, шаблон, импорт | Время до первого результата |
| **Использование** | Повторяемая ценность | Письма в момент struggling moment, не по календарю | Частота Little Hire |

Главная страница обычно для активного поиска и решения; контент для первой мысли и пассивного поиска; страницы сравнения для активного. Ошибка: гнать трафик первой мысли на страницу решения и делать вывод «канал не работает».

## Блок тревог: как собрать

1. Выпиши тревоги из switch-интервью и отзывов конкурентов (слова «боялся», «долго не решался», «а вдруг»).
2. Разбей на снимаемые **до оплаты** (импорт, демо, цена, безопасность) и **после** (поддержка, обучение).
3. Для каждой тревоги до оплаты — конкретный факт, не обещание: «импорт из X за 10 минут, 3 400 команд перенесли», не «простой перенос».
4. Самую сильную тревогу — в подзаголовок hero («без …»).
5. Остальные — в FAQ, сформулированный вопросами человека, а не маркетолога: «Что будет с моими данными, если я уйду?» вместо «Безопасно ли это?».

Тревоги для продуктов на LLM: ошибки, конфиденциальность, «увидят ли, что это ИИ», стоимость при росте. Отвечать явно.

## Привычка: блок перехода

Старое решение — главный конкурент. Страница обязана говорить о нём прямо:
- **Что переносим**: данные, настройки, историю, интеграции.
- **Что сохраняется**: привычные паттерны, экспорт обратно.
- **Сколько это занимает**: минуты и шаги.
- **Можно ли параллельно**: период сосуществования снимает страх необратимости.
- **Не ругать старое**: «вы выросли из таблицы» лучше, чем «таблицы — прошлый век».

Отдельные страницы «переход с X» для каждого крупного конкурента — одновременно ответ на привычку и поисковый интент активного поиска.

## Истории переключения вместо отзывов

Отзыв работает, когда повторяет структуру switch-интервью:
1. **Что было**: старое решение и его push («сводили руками, два раза отправили клиенту ошибку»).
2. **Что случилось**: событие-домино («ушёл клиент»).
3. **Чего боялись**: тревога («думали, перенос займёт неделю»).
4. **Что теперь**: прогресс в их словах и, если есть, цифра («20 минут вместо половины дня»).

Пять таких историй с разными обстоятельствами покрывают сегменты лучше, чем пятьдесят «отличный сервис». Истории берутся из интервью с согласия; слова не редактируются в маркетинговые.

## Поисковые интенты как работы

Запросы — работы в сжатом виде. Разметка:

| Тип запроса | Фаза | Работа | Страница |
|---|---|---|---|
| «почему отчёт клиенту занимает так долго» | Первая мысль | Понять проблему | Статья |
| «как автоматизировать отчёты агентства» | Пассивный → активный | Узнать, что бывает | Гайд, обзор подходов |
| «X vs Y», «альтернативы X» | Активный поиск | Сравнить | Страница сравнения |
| «X цена», «X отзывы» | Решение | Снять тревоги | Цена, кейсы |
| «как перенести из X» | Онбординг | Переход | Инструкция переноса |

Формулировки запросов — готовые заголовки: люди уже назвали работу своими словами. Подробности по интенту и структуре — в `seogeo`.

## Сегментные лендинги

Если обстоятельства расходятся (`competition-and-market.md`), делай отдельные входы:
- По **обстоятельству**, не по демографии: «для агентств с 10+ клиентами» лучше, чем «для малого бизнеса».
- По **исполнителю vs покупателю** в B2B: исполнителю — прогресс в работе, покупателю — контроль, обоснование, стоимость владения.
- По **старому решению**: «переход с таблиц», «переход с X».
- По **фазе таймлайна**: контентная страница, сравнение, цена.

Проверка необходимости: если hero для двух сегментов отличается только словом в заголовке, это один лендинг с переменной. Если расходятся силы и тревоги, это два.

## Письма, уведомления, рассылки

Те же силы в другом канале:
- **Триггер по struggling moment**, не по календарю: письмо «ваш отчёт ушёл с цифрой, которая выбивается» ценнее еженедельного дайджеста.
- **Онбординг-серия по работе**: каждое письмо двигает на шаг карты работы, а не рассказывает про фичу.
- **Возврат ушедших**: назвать push, который мог случиться у них («если отчёты снова делаются руками…»), не «мы скучаем».
- **Повторный Big Hire** для редких работ (раз в год): напоминание перед сезоном работы.

## Шаблон брифа лендинга

```
Исполнитель и обстоятельства: …
Главная работа (глагол + объект + контекст): …
Уровень выше / ниже: … / …
Эмоциональная / социальная стороны: … / …
Фаза таймлайна, на которую страница: …
Push (словами людей, 3 шт.): …
Pull (прогресс словами людей): …
Тревоги до оплаты (3) и факты против них: …
Привычка (старое решение) и план перехода: …
Конкуренты через работу и чем мы лучше / хуже: …
Честные границы (для кого не подходит): …
Первый Little Hire (глагол на кнопке): …
Истории переключения (кто, 4 части): …
Метрика страницы: …
```

## Вопросы для брейншторма

1. Прочитает ли исполнитель в первой строке свою ситуацию? Какими словами он её описывает в интервью?
2. Какой один прогресс мы обещаем? Если три — какой главный?
3. Какая тревога сильнее всего останавливает перед оплатой? Стоит ли она в подзаголовке?
4. Что мы говорим про старое решение? Где блок перехода?
5. Для какой фазы таймлайна эта страница? Куда идёт трафик других фаз?
6. Какие отзывы можно переписать в четыре части истории переключения?
7. Какую категорию мы называем и какую тревогу наследуем?
8. Что произойдёт после клика по кнопке: работа или анкета?

## Анти-паттерны

- Hero про фичи или про нас («платформа нового поколения»).
- Три обещания в заголовке.
- Цена спрятана, тревоги не названы, FAQ отвечает на вопросы маркетолога.
- Отзывы без истории.
- Молчание о старом решении и о переносе.
- Один лендинг на все фазы таймлайна и все сегменты.
- Искусственная срочность и дефицит (см. `nudge`, раздел тёмных паттернов).
- Кнопка «Зарегистрироваться» вместо глагола работы.
