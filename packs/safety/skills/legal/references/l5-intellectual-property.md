# L5. Интеллектуальная собственность

> Код принадлежит тому, кто его написал, пока документ не передал права. Это касается сотрудников, подрядчиков, фрилансеров и ИИ. Чужая библиотека принадлежит её автору на условиях лицензии, которую вы приняли, установив её. Бренд принадлежит тому, кто зарегистрировал знак, а не тому, кто придумал имя.

Нормы: ГК РФ часть 4 — ст. 1225–1254 (общие), 1259–1262 (авторское право, программы), 1270 (исключительное право), 1286, 1286.1 (лицензия, открытая лицензия), 1295–1297 (служебное произведение, заказ, подряд), 1334–1336 (база данных), 1477–1515 (товарные знаки), 1253.1 (посредник); 98-ФЗ (коммерческая тайна); ПП 1236 (реестр российского ПО), ПП 1729 (ИТ-аккредитация); правила open-source лицензий.

## Карта активов и документов

| Актив | Кому принадлежит по умолчанию | Чем оформить | Типовая ошибка |
|---|---|---|---|
| **Код сотрудника** | Работодателю, если служебное произведение (ст. 1295): создано в пределах трудовых обязанностей | Трудовой договор с описанием обязанностей, должностная инструкция, служебное задание или фиксация в трекере, уведомление о создании, акт, **вознаграждение** за служебное (отдельно от зарплаты или явно включённое условием) | Нет обязанностей «разработка ПО» в договоре; нет вознаграждения; через 3 года без использования права возвращаются автору |
| **Код подрядчика / фрилансера** | Подрядчику (ст. 1296: по договору заказа — заказчику, если не указано иное; ст. 1297: по договору подряда без цели создания ПО — подрядчику) | Договор авторского заказа или разработки с **отчуждением** исключительного права (ст. 1234), акт, передача исходников; при ГПХ с физлицом — то же | «Договор оказания услуг» без слова «исключительное право»; лицензия вместо отчуждения; самозанятый без договора |
| **Код от ИИ-ассистента** | По российскому праву автор — только человек; сгенерированное без творческого вклада не охраняется; при существенной доработке — права у дорабатывающего | Фиксировать вклад человека; соблюдать условия провайдера; проверять, не воспроизведён ли чужой код под copyleft | Считать, что «код от Copilot наш» или наоборот бояться использовать |
| **База данных** | Изготовителю (ст. 1334, смежное право при существенных затратах) + авторское на структуру | Документация затрат; договоры | Не фиксировать |
| **Open-source библиотеки** | Авторам; лицензия даёт права | Проверка лицензии до добавления; SBOM с лицензиями; атрибуция (NOTICE, «О программе») | AGPL в SaaS; GPL в проприетарном бинаре; отсутствие атрибуции для MIT/Apache |
| **Дизайн-система, UI-кит другой компании** | Той компании | Лицензионный договор или отчуждение; если «своя вторая компания» — всё равно договор между юрлицами | Использовать «по-дружески» без документа; при продаже бизнеса — дыра в due diligence |
| **Шрифты** | Фаундри | Лицензия на web-использование (OFL — свободно с условиями; коммерческие — покупка на домен/просмотры) | Шрифт с сайта «бесплатно» без лицензии |
| **Иконки, картинки, стоки, видео** | Авторам | Лицензия (CC с условиями, стоковая, покупка); атрибуция где требуется | Картинка из поиска |
| **Контент пользователей** (описания, фото) | Пользователю | Лицензия в соглашении: неисключительная, безвозмездная, на срок размещения, на использование в рамках сервиса (показ, обработка, обезличенная аналитика), без права продажи; гарантия прав; посредник по 1253.1 | Нет лицензии → показ другим без права; оговорка «передаёт все права навсегда» — ущемляющая |
| **Название, логотип, домен** | Никому, пока не зарегистрирован знак | Поиск по базе Роспатента (ФИПС) и Linkmark/Madrid; заявка на товарный знак (классы 42 — ПО/SaaS, 45 — знакомства/соцсети, 9, 35, 38); регистрация домена на юрлицо; ТЗ — 12–18 месяцев, ускорение возможно | Запуск под именем, занятым в классе 45; домен на физлицо-сотрудника |
| **Коммерческая тайна** (алгоритмы, базы, метрики) | Компании при режиме КТ (98-ФЗ): перечень, учёт доступа, гриф, NDA, договоры | Положение о КТ, перечень, NDA, грифы | NDA без режима КТ — защищает слабо |
| **Патент на изобретение / полезную модель** | Автору; для ПО как такового не выдаётся; возможен на техническое решение | Редко оправдан для стартапа | Тратить на это ресурсы вместо знака |

## Open source: быстрый ориентир

| Лицензия | Можно в закрытом продукте | Условия |
|---|---|---|
| MIT, BSD, ISC, Apache 2.0 | Да | Сохранить уведомление об авторстве и лицензию; Apache — NOTICE и указание изменений; Apache несовместим с GPLv2 |
| MPL 2.0 | Да | Изменённые файлы MPL — открыть; остальное можно закрыть |
| LGPL | Да при динамической линковке | Изменения в самой библиотеке — открыть; пользователь должен мочь заменить библиотеку |
| GPLv2/v3 | Только если продукт распространяется (бинарь/исходник) — весь продукт под GPL; для SaaS без распространения — GPL не триггерится | Серверная работа не «распространение» |
| **AGPLv3** | Нет для закрытого SaaS: сетевое взаимодействие = распространение | Весь сервис должен быть открыт под AGPL или покупка коммерческой лицензии (MongoDB SSPL, Grafana AGPL, Minio AGPL, n8n Sustainable Use — читать) |
| SSPL, BSL, «Source-available», Elastic, Commons Clause | Условно | Читать текст: часто запрет на «предоставление как сервис» |
| CC BY / BY-SA / BY-NC / BY-ND | Для контента | Атрибуция; SA — копилефт на производные; NC — некоммерческое; ND — без изменений |
| Без лицензии в репозитории | **Нельзя** | Все права сохранены; просить автора добавить лицензию |

Процесс: SCA-инструмент с лицензиями (license-checker, cargo-deny, FOSSA, ScanCode), allow-list лицензий в CI, файл THIRD-PARTY-NOTICES в продукте, проверка при каждом добавлении. Модели ИИ и датасеты — свои лицензии (Llama, OpenRAIL, CC) с ограничениями на использование.

## Реестр российского ПО и ИТ-аккредитация

- **Реестр отечественного ПО** (ПП 1236, Минцифры): нужен для госзакупок и льготы по НДС (НК ст. 149 п. 2 пп. 26 — реализация прав на ПО из реестра без НДС). Условия: исключительное право у российского лица (>50 % контроля россиян), ПО не содержит компонентов, нарушающих требования (ограничения на иностранные СУБД и зависимости по проверке), лицензия не ограничивает распространение в РФ, выплаты иностранным лицам < 30 % выручки, сайт с описанием и документацией. Open-source зависимости допустимы при свободных лицензиях.
- **ИТ-аккредитация** (ПП 1729): для компаний с ОКВЭД ИТ и долей ИТ-доходов ≥ 30 %, зарплата не ниже средней (или для стартапов — иные критерии), согласие на раскрытие налоговой тайны. Даёт: пониженные страховые взносы, льготный налог на прибыль, ипотека и отсрочка сотрудникам, мораторий на проверки. Аккредитация ИП не предусмотрена.
- Оба требуют чистых прав на код — см. таблицу активов.

## Контент пользователей и посредничество

В соглашении: гарантия, что пользователь обладает правами; лицензия сервису; запрет контента, нарушающего права третьих лиц; процедура жалоб правообладателей (контакт, форма, срок реакции, удаление, восстановление по возражению); журнал. Это делает сервис информационным посредником по ст. 1253.1 и защищает от ответственности за чужое.

## ИИ-сгенерированный контент

- Авторское право: в РФ — автор только гражданин; результат без творческого вклада человека не охраняется, им может пользоваться любой; доработанный человеком — охраняется в части вклада. Для бренда и ключевых текстов — человеческая доработка и фиксация.
- Ответственность за содержание (клевета, нарушение прав, недостоверность) — на том, кто опубликовал.
- Условия провайдера модели: права на вывод (обычно передаются пользователю), запреты (генерация ПДн, медицинских советов без оговорок), обучение на ваших данных (отключить).
- Маркировка ИИ-контента: в РФ обязанности нет (обсуждается); в ЕС — ст. 50 AI Act (см. `l8`, `l9`); хорошая практика — помечать.

## Вопросы для брейншторма

1. Кто писал каждый модуль: сотрудник, подрядчик, ИИ? Какие документы подтверждают права компании?
2. Есть ли в трудовых договорах условия о служебных произведениях и вознаграждении?
3. Какие open-source зависимости с копилефтом в продукте и как он распространяется (SaaS, бинарь, клиент)?
4. Есть ли файл атрибуции для MIT/Apache/OFL?
5. Чья дизайн-система, шрифты, иконки, картинки, и по какому документу?
6. Проверено ли название по классам 42 и 45? Подана ли заявка? На кого домен?
7. Какую лицензию на контент даёт пользователь и что ему гарантируется взамен?
8. Есть ли процедура жалоб правообладателей?
9. Нужен ли реестр ПО или аккредитация, и выполняются ли условия по правам?
10. Что из данных и алгоритмов — коммерческая тайна и введён ли режим?

## Признаки проблемы

Ядро написал фрилансер «по договору услуг» · в трудовом договоре нет «разработка ПО» · AGPL-библиотека в закрытом бэкенде · шрифт куплен «для одного сайта» и используется в приложении · субмодуль дизайн-системы из другой компании без договора · имя сервиса совпадает со знаком в 45 классе · в соглашении нет лицензии на контент · NDA без режима КТ.
