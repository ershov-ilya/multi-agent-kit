# Пример пака для продуктовой аналитики

Первый сценарий — «Покажи, где просела воронка регистрации за прошлую неделю, и предложи гипотезу». Результат содержит шаги и объёмы воронки, переход с наибольшим падением относительно сопоставимого периода, ограничения данных и гипотезу для проверки.

| Компонент | Что входит в сценарий |
| --- | --- |
| `skills/analyze-funnel/SKILL.md` | Определяет шаги и знаменатели, подбирает сопоставимый период, учитывает объём выборки и формирует отчёт. |
| `skills/analyze-funnel/references/metrics.md` | Хранит определения событий, правила сегментации и примеры расчётов. |
| MCP Tool `get_funnel` | Читает агрегаты. Принимает идентификатор воронки, период, часовой пояс и, если нужно, фильтр сегмента. Возвращает числа по шагам, применённые фильтры и признаки неполного периода. |

Имена и схема инструмента условные. При реализации проверь, что существующий сервер аналитики возвращает данные для сравнения. Например, если ответ не включает сравниваемый период, вызови инструмент повторно с теми же фильтрами и соответствующими датами.

Если нужен отдельный сценарий записи в бэклог, добавь узкий инструмент `create_backlog_item`. Агент формирует черновик из отчёта и создаёт задачу после авторизации на запись в конкретный проект. Инструмент возвращает идентификатор и ссылку. Для повторов используй поддерживаемую трекером идемпотентность или сначала проверяй, создана ли задача.

## Проверки на тестовых данных

- Скилл выбирается по запросу о воронке. Инструмент получает ожидаемый идентификатор воронки, периоды и фильтры. Отчёт показывает знаменатели конверсий и связывает гипотезу с наблюдением.
- При неполном периоде или отсутствии базового периода отчёт отмечает ограничение и опускает вывод о динамике.
- Запрос на анализ завершается отчётом. Если пользователь дополнительно заказал запись, а трекер недоступен или запретил её, агент возвращает черновик без идентификатора созданной задачи.
