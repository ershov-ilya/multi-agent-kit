# Техническое SEO: краул, индексация, рендеринг, скорость, разметка

Что здесь: факты, которые нужно знать при архитектуре сайта и продукта. Метки: **✔** официальная документация Google или Яндекса; **~** практика или вторичный источник.

## 1. Краулинг и доступность

| Элемент | Правило ✔ | Типичная ошибка |
|---|---|---|
| **robots.txt** | RFC 9309; Google читает до 500 КиБ; `Disallow` блокирует краул, **не индексацию** (URL может попасть в индекс по ссылкам без контента); `noindex` в robots не поддерживается с 2019 | Закрыть CSS и JS; закрыть страницу, которую надо выкинуть из индекса (нужен noindex, а для него страница должна быть доступна) |
| **noindex** | Мета-тег или заголовок `X-Robots-Tag` (для PDF и картинок); страница должна быть доступна для краула; долгий noindex со временем работает и как nofollow (Mueller ~) | Снимать noindex через JS (Google может не рендерить) |
| **Sitemap** | До 50 000 URL и 50 МБ на файл, индекс sitemap для больших; `lastmod` учитывается, если честный; `priority` и `changefreq` игнорируются | Неканонические, редиректящие и noindex URL в sitemap |
| **Статус-коды** | 301 и 302 оба передают PageRank (Gary Illyes 2016); разница в канонизации: 301 — сильный сигнал, какой URL главный, 302 — слабый; 410 чуть быстрее 404 для удалённых; **soft 404** (страница «не найдено» с кодом 200) выкидывается из индекса | Цепочки редиректов; SPA отдаёт 200 на всё |
| **Mobile-first** | Завершён 5 июля 2024: все сайты краулятся Googlebot Smartphone; недоступный с мобильных не индексируется | Разный контент на мобильной и десктопной версии |
| **Бюджет краула** | Нужен сайтам от 1 млн страниц или от 10 тыс. с ежедневными изменениями; управляется инвентарём URL: закрыть мусор, склеить дубли, 404/410 | Открытые фасеты, сортировки, календарь, session id |
| **IndexNow** | Bing и Яндекс (с 2021); Google не внедрил; Indexing API Google только для вакансий и трансляций | Ждать от IndexNow эффекта в Google |

## 2. Рендеринг и JavaScript ✔

- Googlebot рендерит на evergreen Chromium, но через **очередь**: от секунд до дней. Страницы с не-200 могут не рендериться. `noindex` в сыром HTML может отменить рендер.
- **Googlebot не взаимодействует**: не кликает, не скроллит, не заполняет формы. Контент за кликом, табом, «показать ещё», бесконечной прокруткой без пагинации невидим.
- **Фрагменты `#` не краулятся** как отдельные страницы. Роутинг через History API и настоящие `<a href>`.
- Ленивая загрузка должна срабатывать без взаимодействия (IntersectionObserver; `loading="lazy"` для картинок; Googlebot использует высокий вьюпорт).
- Нельзя полагаться на `localStorage` и cookies для контента. SPA должны отдавать настоящие статус-коды (иначе soft 404).
- Индексируется **отрендеренный HTML**; проверяй через URL Inspection.
- **AI-краулеры JS не исполняют**: исследование Vercel и MERJ (500 млн запросов GPTBot): ноль исполнения JS ~. Для ChatGPT, Claude, Perplexity CSR-лендинг — пустая страница.
- Решение по умолчанию: **SSR или SSG** для всего индексируемого; гидрация поверх. Onely: до 7-го уровня по JS-ссылкам Googlebot доходил за 313 часов против 36 по HTML (малая выборка ~).

## 2a. Фреймворки, одностраничники и анимации

**Правило**: весь текст, ссылки, цены и заголовки присутствуют в HTML ответа сервера. Анимации, табы и аккордеоны — поверх уже отрендеренного контента, не вместо него.

| Фреймворк | Как получить индексируемый HTML | Ловушки |
|---|---|---|
| **Next.js** (App Router) | Серверные компоненты и SSG по умолчанию; ISR для часто меняющихся страниц; `generateMetadata` для title, description, canonical, hreflang; `notFound()` для настоящего 404; редиректы в `next.config` или middleware; `sitemap.ts` и `robots.ts` | `'use client'` на всём макете; данные только в `useEffect`; динамические маршруты без `generateStaticParams`; прокси документации через rewrites с относительными ссылками, ломающими canonical |
| **Nuxt** | SSR или `nuxt generate`; `useSeoMeta`; `createError({statusCode: 404})` | `ssr: false` глобально |
| **SvelteKit, Remix, Astro** | SSR и статическая генерация из коробки; Astro отдаёт HTML без JS по умолчанию | Контент в островках, грузящихся на клиенте |
| **Чистый React и Vue SPA** | Пререндер (Prerender.io, rendertron) или миграция на мета-фреймворк | Hash-роутинг; один `<title>` на все экраны; 200 на всё |

**Одностраничный лендинг**: если маркетинг хочет один экран с анимациями, индексироваться будет одна страница с одним интентом. Пять сегментов — пять URL с собственными title, H1, первым экраном и FAQ; общий дизайн не мешает.

**Анимации и индексируемость**:
- Текст, появляющийся по скроллу через CSS (`opacity: 0` → `1`, `transform`), в HTML присутствует, Google и AI-боты его читают. Текст, **вставляемый JS по скроллу** (lazy-инъекция контента), для AI-ботов невидим, для Google зависит от рендера без скролла.
- Googlebot не скроллит: IntersectionObserver-анимации допустимы, если контент уже в DOM; ленивая подгрузка блоков по событию скролла — нет.
- Табы и аккордеоны: содержимое в DOM, скрыто CSS; Google индексирует скрытый контент, но для сниппетов и пассажей предпочитает видимый.
- `prefers-reduced-motion` уважать; тяжёлые анимации бьют по INP и LCP, а это конверсия.
- Hero на canvas или WebGL без текстовой подложки: H1 и первый абзац должны быть в HTML рядом.
- Проверка: `curl` без JS или URL Inspection в GSC, отрендеренный HTML должен содержать весь текст страницы.

## 3. Канонизация и дубли ✔

- rel=canonical — **подсказка**. Сигналы выбора: HTTPS, sitemap, canonical, редиректы, внутренние ссылки, hreflang-кластер, похожесть контента.
- Один канонический хост (www или нет, https) с 301 со всех остальных.
- Параметры: единый порядок, `?key=value`, разделитель `&`; трекинговые параметры не в внутренних ссылках.
- Варианты товара: свой URL допустим, canonical на URL без параметров, в sitemap только канониклы.
- Пагинация: уникальный URL на страницу, self-canonical (не на первую), настоящие ссылки; rel=prev/next не используется с 2019.
- Бесконечная прокрутка: дублировать пагинированными URL через `pushState`.
- Фасеты: если не индексируем — robots или `#`; если часть индексируем — canonical на нефильтрованную, 404 для пустых комбинаций (подробно в `product-playbooks.md`).
- A/B-тесты: варианты на других URL → canonical на оригинал; редирект-тест через 302; без клоакинга.

## 4. Международность ✔

- **hreflang**: взаимные ссылки обязательны; язык ISO 639-1 плюс необязательный регион ISO 3166-1; `x-default` для страницы выбора или запасной; каждая страница перечисляет себя; через `<link>`, HTTP-заголовки или sitemap. Hreflang не заменяет canonical: каждая языковая версия канонична сама себе.
- Язык в URL (подпапка `/de/` предпочтительна), не по заголовку Accept-Language и не по IP (краулеры не шлют языковые предпочтения; Etsy потерял неанглийские ранжирования ~).
- Без автоматического редиректа по гео без доступной альтернативы.
- Яндекс: регион сайта назначается в Вебмастере и Яндекс Бизнесе; региональные поддомены или разделы для геозависимых запросов.

## 5. Core Web Vitals ✔

| Метрика | Хорошо | Плохо | Что измеряет |
|---|---|---|---|
| **LCP** | ≤ 2,5 с | > 4,0 с | Отрисовка самого большого элемента |
| **INP** | ≤ 200 мс | > 500 мс | Задержка реакции на взаимодействие; **заменил FID 12 марта 2024** |
| **CLS** | ≤ 0,1 | > 0,25 | Сдвиги макета |

- Порог — **75-й перцентиль** загрузок, мобильные и десктоп отдельно.
- Ранжирование и Search Console используют **полевые данные CrUX** (Chrome, 28-дневное окно). Lighthouse — лабораторные, для диагностики. Нет трафика в CrUX — нет данных.
- История сигналов: HTTPS (2014), mobile-friendly (2015), навязчивые интерстишлы (январь 2017), page experience (2021–2022); в апреле 2023 убраны из списка систем, остались сигналами. Google: релевантность контента перевешивает page experience. Эффект на ранжирование малый; эффект на конверсию большой (кейсы в `case-studies.md`).
- 2025–2026: LoAF API для отладки INP; экспериментальные метрики **soft navigations** для SPA добавлены в CrUX 13 октября 2026, стабильные CWV не изменились, цель — выход из эксперимента в мае 2027. «Engagement Reliability» как новый Web Vital — не существует.

Что обычно чинит CWV: SSR вместо клиентских виджетов для hero, размеры картинок и `fetchpriority`, отложенные третьи стороны, `font-display`, резерв места под рекламу и баннеры, разбиение длинных задач JS.

## 6. Структурированные данные ✔

**Что убрано**: FAQ rich results только для авторитетных gov и health сайтов (август 2023); HowTo удалён (сентябрь 2023); блок поиска по сайту в сайтлинках (ноябрь 2024); **12 июня 2025** деприкейтнуты Book Actions, Course Info, Claim Review, Estimated Salary, Learning Video, Special Announcement, Vehicle Listing; Practice Problem с января 2026 (Dataset — не подтверждено).

**Что работает**: Article, BreadcrumbList, Event, **Product** (merchant listing и product snippet), Review snippet, Recipe, Video, JobPosting, LocalBusiness, **Organization** (расширена в 2024: логотип, контакты, идентификаторы), ProfilePage, DiscussionForum, Q&A, SoftwareApplication, Carousel, image metadata, VacationRental.

**Правила**: разметка соответствует видимому тексту (иначе ручная санкция «спамная разметка»); JSON-LD предпочтителен; проверка в Rich Results Test (право на rich results Google) и Schema Markup Validator (синтаксис schema.org). Для AI-поиска Google: разметка «не требуется», но помогает пониманию; Microsoft говорит, что schema помогает их LLM.

**Яндекс**: schema.org, Open Graph, микроформаты; свой валидатор; неподдерживаемое игнорируется.

## 7. Заголовки, сниппеты, сайт-нейм ✔

- Google генерирует title из `<title>`, H1, заметного текста, анкоров, имени сайта; `<title>` используется ~87% времени. Переписывает длинные, переспамленные, шаблонные, пустые и дублирующиеся. Zyppy: переписано 61,6% title, чаще при >600 px и с разделителем «|»; совпадение H1 и title резко снижает переписывание ~.
- Meta description переписывается ~63% времени (Ahrefs 2020 ~); показывается, когда описывает страницу лучше текста.
- Длины: официальных лимитов нет; title усекается около 600 px (~50–60 символов), описание ~155–160 символов на десктопе.
- **Favicon**: квадрат, минимум 8×8, рекомендовано ≥ 48×48, один на хост, доступен для краула. **Site name**: из `WebSite` schema (`name`, `alternateName`), `og:site_name`, заголовков; поддоменные имена с 2023.

## 8. Чеклист технического аудита

1. Один хост, HTTPS, 301 со всех вариантов.
2. robots.txt не закрывает CSS, JS, нужные разделы; staging закрыт авторизацией и noindex.
3. Sitemap только с каноническими индексируемыми URL, `lastmod` честный.
4. Отчёт индексации GSC: доли «Crawled – not indexed» и «Discovered – not indexed», soft 404, дубли с другим канониклом.
5. Рендеринг: сравнить сырой HTML и отрендеренный; контент и ссылки есть в HTML без JS; статус-коды верные.
6. Пагинация, фасеты, сортировки, внутренний поиск под контролем.
7. hreflang взаимный, язык в URL, без гео-редиректа.
8. CWV по CrUX: LCP, INP, CLS на 75-м перцентиле по шаблонам страниц.
9. Разметка валидна и соответствует видимому; удалённые типы не ждать.
10. Title ≈ H1, уникальны; описания есть на ключевых шаблонах; favicon и site name настроены.
11. Логи сервера: куда ходит Googlebot, где 5xx и 404, доля мусорных URL.
12. Для AI-поиска: не заблокированы OAI-SearchBot, PerplexityBot, ClaudeBot, если хотите цитирования; контент в HTML.
