# ADR-0001: границы workspace

## Контекст

Нужен монорепо с несколькими корнями в IDE: оркестратор отдельно от кода, клиент отдельно от движка,
один git на все корни.

## Решение

1. `workspace/` — оркестратор, qa, devops, ADR/RFC/OPS. Кода клиента и движка здесь нет.
2. `web/` — единственный источник экранов и клиентского поведения.
3. `engine/` — единственный источник доменных правил. Без UI. HTTP-сервер здесь не поднимать, пока
   отдельный ADR не решит иначе.
4. Открывать `workspace/{{project.name}}.code-workspace`: папки `workspace`, `web`, `engine` одного
   репозитория.
5. Каркас приложение не инициализирует: исходников клиента и движка нет.
6. Агенты: `orchestrator`, `web-subagent`, `engine-subagent`, `qa`, `devops`.

## Последствия

Оркестратор не пишет код в `web/` и `engine/`. Клиент не становится вторым источником правил. Новый
контур заводится соседней папкой по `workspace/agent-kit/context/new-subproject.md`, в тот же git.
Секреты в git не класть.
