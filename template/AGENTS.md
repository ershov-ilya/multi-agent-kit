# AGENTS.md — {{project.name}}

Вход для агента. Монорепо с одним git-корнем и тремя корнями в IDE: оркестрация, клиент и движок.
Если этот файл расходится с ADR, побеждает ADR в `workspace/docs/decisions/`. Обзор для человека —
`workspace/README.md`. Секреты и `.env` в git не класть. Коммит и выкладку делать только по явной
просьбе.

## С чего начать

1. Прочитай этот файл.
2. Границы продукта — `workspace/docs/decisions/ACTIVE.md`, затем нужный ADR. Смысл каркаса —
   `workspace/docs/project/overview.md`, контекст продукта — `workspace/agent-kit/context/project.md`.
3. Локальный контекст зоны — `web/AGENTS.md` или `engine/AGENTS.md`.
4. Контракт наружу — `docs/expose/` того корня, который его отдаёт.
5. Код правь только в зоне задачи.

## Субпроекты

| Папка | Что это | Чего здесь нет |
|-------|---------|----------------|
| `workspace/` | Оркестрация, ADR/RFC/OPS, qa, devops | Кода клиента и движка |
| `web/` | Клиент | Доменных правил и расчётов |
| `engine/` | Доменная логика без UI | Экранов и HTTP-сервера, пока ADR не решит иначе |

Клиент не повторяет правила движка. Движок не рисует экраны. Выкладка — зона `devops`.
Новый субпроект — по `workspace/agent-kit/context/new-subproject.md`.

## Агенты

Оркестратор не пишет код `web/` и `engine/`, если задачу можно отдать субагенту.

| Имя | Когда | Зона |
|-----|-------|------|
| `orchestrator` | всегда | декомпозиция, ADR, сводка |
| `web-subagent` | экраны и клиент | `web/` |
| `engine-subagent` | правила и расчёты | `engine/` |
| `qa` | проверка поведения | `workspace/` |
| `devops` | выкладка и хосты | прод |
| `decision-review` | проверка RFC, ADR и OPS | `workspace/docs/decisions/` |
| `search` | факты из сети | — |

Исходники агентов, правил, команд и скиллов проекта — в `workspace/agent-kit/`. Общие паки
подключены в `multi-agent-kit.json`.

## Документы

| Папка | Роль |
|-------|------|
| `docs/decisions/` | ADR (решение), RFC (предложение), OPS (как делали и что проверить) |
| `docs/expose/` | контракт наружу |
| `docs/project/` | как устроено, без статуса решения |

Решения продукта — только `workspace/docs/decisions/`. Локальные `web/docs/decisions/` и
`engine/docs/decisions/` платформенный канон не дублируют. Фиксация итерации — команда `/adr`.

## Границы

- Один git-корень на `workspace/`, `web/` и `engine/`. Отдельный репозиторий на субпроект не заводить.
- Стек клиента, связь корней и хост выкладки не выбраны, пока нет ADR.
- Секреты, ключи и `.env` в git не писать.
